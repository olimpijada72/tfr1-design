    01

    ArcRefine

    Friday, 2 hr, hard stop

    FoldArc · Ken Osumi · October 2026 · structural carryover

    What it is

    A method that refines an existing binder's sequence while preserving its binding position and orientation. The mechanism, which they call structural carryover, is that the binder–target complex is predicted once with Boltz-2, and every subsequent sequence update begins from the previous prediction's structural information instead of being predicted from scratch. The structure is not frozen, so sequence and shape can both move, but the pose is carried forward rather than rediscovered each round.

    The positioning is explicit: it is meant to fill the gap between tools that generate a pose at a chosen site, like RFdiffusion, and tools that optimise a sequence, like BindCraft, so that the arrangement is not lost in the handoff between them.

    Why it matters to this project specifically

    In stage 5 you graft a histidine into the interface core, and the most likely single outcome is that it destroys the interface. Your only current response is to discard that variant.

    ArcRefine offers a different response: keep the pose, keep the histidine, re-optimise everything around it. That converts your largest source of attrition into a repair step.

    This is worth real money at that point in the funnel, because by Friday the pool is only a few dozen designs deep and every variant lost to a broken interface is a submission slot you cannot fill.

    The evidence

    TestOptimizedUnoptimizedKind

    Read the caveats, which the page states itself

    Candidates were selected independently for each group, so the comparison reflects the output of whole workflows and does not isolate the effect of structural carryover. The results also do not demonstrate that binding occurs at the predicted site. That is unusually candid for a method page, and it is the right way to read the numbers above.

    02

    BioNeMo Agent Toolkit

    Spike today — 2 hours

    NVIDIA · github.com/NVIDIA-BioNeMo/bionemo-agent-toolkit

    What it is

    A set of agent skills wrapping NVIDIA's biology models — installable directly into Claude Code, which is what you are already using, so the integration cost is close to zero. Each skill bundles instructions, scripts and references so an agent can select a tool, prepare its inputs, run it and interpret the output. Install is a single command of the form npx skills add NVIDIA-BioNeMo/bionemo-agent-toolkit --skill <name>. Code is Apache-2.0, skills and docs are CC-BY-4.0.

    The part that matters

    There is a workflow called generative-protein-binder-design offering two routes.

    RouteChainsRelation to your plan
    protein-binder-designRFdiffusion → ProteinMPNN → Boltz-2 / OpenFold3, as NIM servicesThe route section 04 rejected — pre-orchestrated
    complexa-binder-designProteina-Complexa reward-guided co-design, AF2 reward gate, validated with Boltz-2 / OpenFold3A second path to the model in section 04

    Both routes resolve the target and its hotspots, generate candidates, co-fold each independently, and rank on ipTM, ipSAE, pLDDT and apo↔holo RMSD — which is very nearly the exact filter stack specified in section 05 of the plan, ipSAE included. That stack was going to cost you an afternoon of scripting.

    The whole argument for BindCraft in section 04 was setup risk: three codebases, three dependency stacks, one evening lost to a version conflict. This toolkit may have removed that argument, because the three-tool route comes pre-orchestrated and the models can run as hosted NIM endpoints needing only an NGC_API_KEY rather than a local GPU.

    If that holds, you get the cost profile of the RFdiffusion route without the setup risk that made it unacceptable. And since you already hold Brev credits, you are inside NVIDIA's ecosystem anyway.

    For
    • Removes the one objection that decided section 04
    • Hosted NIMs may mean no local GPU for stages 2–4
    • Ships the ipSAE filter stack you were going to build
    • Installs into the tool you are already working in
    Against
    • Several skills marked pending validation in the README
    • Hosted evaluations use single test cases
    • NIM quota and rate limits unknown — a run of thousands of designs is exactly where a limit bites
    • New infrastructure, not a settled tool
    Spike design — two hours, today
    • Install the protein-binder-design skill and run its own example target.
    • Success criterion: one binder designed end to end against their example, not yours. Do not substitute TfR1 — that conflates two unknowns.
    • Record wall-clock time and whether anything hit a rate limit.
    • Install BindCraft tonight regardless. This spike does not replace that.

    RFD4-Proteina

    Not this week — note it for version two

    Institute for Protein Design (UW) + NVIDIA · Baker & Didi · rfd4-proteina.org · code

    What it is

    A design model working in a shared latent space that spans standard and modified amino acids, sugars, DNA and RNA. It combines two kinds of reasoning: intrinsic, meaning recurrent refinement that adaptively allocates compute, and extrinsic, meaning beam search guided by scores such as energetics or geometric criteria. BSD-3-Clause code, weights on Hugging Face, a PyPI package, and wet-lab validation across a wide range of target classes.

    Speed at 200 res1.35 s vs RFD3's 5.12 s
    Peak memory1.36 GB vs RFD3's 8.50 GB
    Licence (code)BSD-3-Clause

    The question you are actually asking

    Reward-guided search means designs are scored mid-generation against an objective. The obvious hope is that you plug in a pH reward and requirement ③ stops being unmeasurable.

    It does not work, and the reason is worth understanding properly rather than taking on trust.

    What would work, for version two

    A pure-geometry histidine reward: score a design on whether a histidine sits in the interface core within salt-bridge distance of an arginine or lysine on the target. That needs only coordinates — no pKa prediction — so it is perfectly computable on intermediate states.

    This is the first idea in the whole project that could move requirement ③ from sampled to optimised.

    And it is unambiguously not an eight-day task. The custom reward path is documented only for the NIM route — write a reward.py callback, mount it at /opt/nim/reward.py, set NIM_ALLOW_ORACLE_PLUGIN=true, relaunch the service, then reference the metric key in the search request's weights. The equivalent for the open model is not documented in the blog at all. Write it down and come back to it.

    04

    Proteina-Complexa

    Reserve — behind both other engines

    NVIDIA · ICLR 2026 oral · code · paper

    What it is

    A flow-matching generative model that designs backbone, side-chain conformations and sequence jointly and fully atomistically, built on La-Proteina, with inference-time optimisation against reward models including AF2, RoseTTAFold3 and force fields, using beam search, MCTS, best-of-N and FK steering.

    Why it is the serious challenger

    The paper reports that its test-time optimisation outperforms earlier hallucination methods under normalised compute budgets. Hallucination is precisely what BindCraft does. That is a like-for-like claim against your chosen engine at matched cost, which is the only kind of comparison worth acting on.

    Why it is in reserve anyway

    Note the second route

    The BioNeMo toolkit's complexa-binder-design skill reaches this same model through a pre-orchestrated path with an AF2 reward gate and independent Boltz-2 validation. If today's spike goes well, that is a far cheaper way to try Proteina-Complexa than standing the repo up yourself — and it is the same two hours.

    What this changes

    One thing, and it is a real one. The section 04 decision is now contested rather than settled. BindCraft was chosen because the assemble-it-yourself route carried unacceptable setup risk; the BioNeMo toolkit may have removed that risk. Neither of us can resolve that from documentation. It needs a run.

    Everything else stays as written. The pipeline shape, the funnel widths, the pH strategy, the portfolio allocation and the calendar are all unaffected by these four tools.
